# Debug Wave — invariants, ruled-out facts, and the bug log

The "survive the domain model" gate depends on knowing what is *correct by design*. A hunter that flags a design choice as a bug wastes a wave; a hunter that dismisses a real bug as "probably intended" misses it. This file is the shared memory that keeps both from happening. Read it before a wave; append to it after.

## Standing invariants a hunter must not violate

These are load-bearing facts about the framework. A red test that only "works" by contradicting one of these is testing a fantasy, not a bug.

- **Global event ids are strictly monotonic.** A later commit always gets a higher `id` than any earlier one. Any argument that depends on a future commit landing at a *lower* id — "the scan skips it", "the watermark advances past it" — is invalid. This single fact killed the #1254 false positive: advancing an empty-fetch stream to a window-max can never skip a future event, because a future event will have a higher id than the window-max.
- **`fetch_window_at` fallback is load-bearing.** In `drain-cycle.ts`, `const at = entry.fetch.events.at(-1)?.id || fetch_window_at` — the `fetch_window_at` fallback is what lets an empty-fetch stream advance so settle converges. Changing it to `?? lease.at` (or similar) hangs the notify/scope suites in an infinite settle loop. Not a bug.
- **The framework has no built-in dedup, by design.** See `docs/docs/architecture/concurrency-model.md` ("why no framework-level dedup"). Do not report "the same event could be delivered twice under X" as a bug — at-least-once with consumer-side idempotency is the deliberate contract.
- **Reaction backoff is a persisted per-stream schedule** (since #1262). A retry-with-backoff persists `deferred_at = now + delay` via a due-marked `ack` and releases the lease, so every worker honors the window (the store excludes the stream from `claim`), `retry` advances once per real attempt, and a stream blocks after exactly `maxRetries` attempts regardless of worker count. The due-ack carries the climbing `retry` (budget survives the window); an explicit defer passes `retry: -1` (not a failure). Do **not** re-report the old "per-worker, N× amplification, floor = max(configured, leaseMillis)" behavior — that was the #1262 bug, now fixed. See `docs/docs/concepts/error-handling.md` § Backoff.
- **`created` is not monotonic with `id`.** Restore preserves source timestamps verbatim, so timestamp order can diverge from insertion order. Time bounds (`created_before`/`created_after`) are pure filters, never id-ordered early-breaks. (This was #1258; the principle stands for any new code that touches `created`.)
- **Fairness is store-internal by design.** The `Store.claim` signature did not change for the #1223/#1252 fairness reserve — each adapter infers the `fair = lagging>=2 ? max(1, floor(lagging/4)) : 0` split inline. Do not propose exposing fairness through the claim interface; that reshape was explicitly rejected.
- **Close/autoclose surfaces are days-only.** Never ms/seconds/minutes on a close-facing API. The one-day floor is deliberate — close is low-cadence housekeeping. Not a bug.
- **Windowed close prunes, it does not retire.** `close`/`.autocloses` delete only the prefix below the closest safe `__snapshot__`; no tombstone, subscriptions and cache untouched, stream stays live. No qualifying snapshot ⇒ `skipped`, not an error.
- **Some InMemory shortcuts are legitimate.** InMemory is single-process and dev/test-only. `notify` is intentionally unimplemented. Not every InMemory-vs-SQL difference is a divergence — check whether the doc-comment declares the behavior best-effort or capability-gated (e.g. `query_streams.source_matches` MAY return a superset) before calling it a bug.
- **A sensitive-bearing state cannot snapshot via `.snap(...)` — enforced at build time, but `restart: true` bypasses it.** `act-builder.ts:665-674` throws at `act().build()` if a state whose events carry `sensitive()` fields also declares `.snap(...)` ("Snapshots write derived state into `__snapshot__.data`, which `forget_pii` cannot reach"). **CORRECTION (wave 14, #1397):** the wave-6 claim that a PII state therefore "never produces a `__snapshot__` event — structurally impossible" is FALSE. `close({restart:true})` seeds a `__snapshot__` with an *actorless* (default-denied) fold, writing `[REDACTED]` and then deleting the plaintext. The build guard covers the declaration path only; the close path never consults `restart_supported`. Snapshot-based PII *resurrection* remains foreclosed (the seed holds the sentinel, not plaintext) — but "a PII state never snapshots" must not be assumed.
- **Lifecycle listeners are contained, not fatal (since #1373).** A throwing `acked`/`blocked`/`closed` listener is logged and swallowed; the drain cycle still finalizes, the remaining sinks still fire, `drain()` returns its real result, and no `error` (circuit-breaker) event is emitted. Do not re-report the *contained* behavior as a swallowed bug — it is the documented contract (`observability.md`, plus a `behavior-contracts.md` row). **CORRECTION (wave 14, #1388):** the original wording claimed "a genuine store failure inside `on_close`'s close machinery still reaches the breaker." That is FALSE in master — `on_close` is not an emit (it runs `run_close_cycle`: load, tombstone, archive, truncate, and only then emits `closed`), and #1376 wrapped the whole thing in `contain_async`, so real `StoreError`s are swallowed. The line described the intent of the fix, not the shipped code, and nothing executable pinned it.
- **Framework-internal `query_streams` walks are paged, and the two markers are treated asymmetrically.** Callers wanting every stream use the internal `walk_streams` helper (since #1371) rather than the store default of `limit: 100`. Separately (since #1374), the audit's shared stat scan excludes `SNAP_EVENT` so heads and counts are DOMAIN figures, but deliberately does **not** exclude `TOMBSTONE_EVENT` — a tombstoned stream really is closed and the `startsWith("__")` head check is what recognizes it. Do not "fix" that asymmetry; filtering both markers trades one bug for its mirror image.
- **There is exactly ONE date reviver (since #1380).** `dateReviver` is exported from `@rotorsoft/act` (`utils.ts`, RFC 1380) and imported by every adapter; the previous per-adapter copies in `act-pg/src/utils.ts` and `act-sqlite/src/sqlite-store.ts` are gone. Adapters must apply it to **every** JSON column they read, including decrypted `pii` (`decrypt` takes an optional reviver). A value's runtime type must never depend on which column it sits in or whether `pii_encryption` is on. A new adapter that hand-rolls its own ISO-8601 regex is a defect, not a style choice.
- **SQLite stores `deferred_at` as a fixed-width ISO-8601 UTC string; it is NOT a divergence.** `defer`/due-ack store `new Date(ms).toISOString()` and `claim` compares against `new Date().toISOString()` — same fixed-width format, so lexicographic == chronological for all realistic dates (only misorders at year ≥ 10000, unreachable). `query_streams` reverts to ms via `getTime()`, matching PG's `.getTime()` and InMemory's raw ms; whole-ms integers round-trip exactly. Verified across a 10-scenario differential (InMemory ≡ PG ≡ SQLite). Do not re-file SQLite `deferred_at` reporting/claim-eligibility as a bug. *(Latent test-coverage gap, not a live bug: `store-differential-tck.ts:816-841` omits `deferred_at` and the `leased_until` value from its comparison row — a future adapter refactor touching `deferred_at` reporting wouldn't be caught; adding it to that row would close the gap.)*

## Confirmed bugs (regression anchors)

Each of these was found red-first and filed. Future waves should confirm they stay fixed and look for siblings.

- **#1257** — `InMemoryStore.restore` kept `pii` inline and never wrote/rolled-back `_pii`, so `forget_pii` no-opped on restored events. Fixed: split pii into `_pii` on restore. *Sibling to check:* any other path that writes events bypassing the `commit` pii-split.
- **#1258** — InMemory `query` early-`break`ed on `created_before`/`created_after`, dropping matches when created order ≠ id order. Fixed: `continue`, not `break`. *Sibling:* any other loop that assumes `created` tracks `id`.
- **#1261** — time-travel `load({ created_before })` returns wrong (empty) state when a snapshot exists after the cutoff; the `with_snaps` resume floor ignores the time bound (all three adapters). *Sibling:* the `created_after` half of the same branch.
- **#1262** — backoff "phantom retry": claiming a stream inside its process-local backoff window bumped persisted `retry` with no handler run, silently halving effective `maxRetries`. Fixed by persisting the backoff window to `deferred_at` (a due-marked `ack` carrying the climbing `retry`), so the store excludes the stream from `claim` during the window. This also refined the `ack` due-marker contract: due-ack now persists the lease's `retry` instead of hardcoding `-1`. *Sibling:* any finalize/claim path where `retry` advances without a real attempt.
- **#1263** — `InMemoryStore.block()` on an already-blocked stream returns the lease again (spurious duplicate `blocked` event); PG/SQLite return `[]`. *Sibling:* other InMemory mutators missing a state-guard the SQL `WHERE` clause enforces.
- **#1255** — correlate-cycle didn't update `entry.lane` when a higher-priority reaction won the priority merge. Fixed. *Sibling:* other per-entry fields that should follow the priority winner.
- **#1277** — `IAct.query`/`query_array` (`act.ts:1228`/`:1268`) hand store events straight to the caller with no `pii_gate`, leaking plaintext PII on all three adapters (worst on PG, which decrypts at-rest ciphertext first). The disclosure gate lives only in `load`. Fail-safe fix is default-deny in the orchestrator (query carries no actor). *Sibling:* any other read surface that returns committed events without routing through `pii_gate`.
- **#1278** — partial-progress + backoff drops the persisted `deferred_at` window: the drain-cycle ack ternary (`drain-cycle.ts:243-249`) reaches the `at: acked_at` branch whenever `handled > 0`, so the `next_attempt_at` (due) branch is unreachable and the window/retry are lost. The #1262 sibling the invariants anticipated. Recoverable degradation (watermark still correct), medium. *Sibling:* any other finalize path where `due` and `at` are mutually exclusive but both are needed.
- **#1279** — `act-notify` `RedisBroker` disposer calls `unsubscribe(channel)` with no listener arg (`redis.ts:70-72`), which node-redis v4 treats as remove-ALL-listeners — so disposing one subscriber on a shared broker silences co-subscribers. The existing `brokers.spec.ts` fake masks it (single-listener overwrite semantics). Wakeup-only degradation, durability intact.
- **#1280** — tRPC `status_to_trpc_code` (`trpc/index.ts:231-234`) maps `ConcurrencyError`→409 and `StreamClosedError`→412, diverging from Hono/OpenAPI (412/410). Documented-and-tested, so a deliberate-but-inconsistent mapping, not silently-wrong data. Medium. *(Fixed: map by identity — Concurrency→412, StreamClosed→404 as the one documented tRPC-has-no-410 exception.)*
- **#1286** — tRPC generator inlines `options.actor()` in the mutation try (`trpc/index.ts:349`), so an actor "throw to deny" → 500, while Hono's `authenticated` returns 401. Breaks the guide's explicit "throw-to-deny is identical / both UNAUTHORIZED" promise. *Sibling:* other per-transport seams (stream/expectedVersion resolver throw) the inline trpc path doesn't map.
- **#1287** — OpenAPI marks `Idempotency-Key` `required:false` (`openapi/index.ts:357`) but the route 400s when it's absent (idempotency on). Doc/route mismatch. *Sibling:* the `If-Match` param's emitted optionality vs actual enforcement.
- **#1288** — `DeferTimer.schedule` (`defer-timer.ts:101`) clamps waits to ~24.8 days and its comment claims `on_wake` re-arms, but the consumer's `on_wake` (`drain-cycle.ts:373`) only sets `_armed`; the arm-triggered drain early-returns before the `:538` re-schedule. So a defer/cooldown > 24.8 days loses its wake and leaks in `_due`. Fix: self-re-arm in the fire callback when `_due.size > 0`.
- **#1293** — `receiver()` finalizes every delivery twice: the route calls `options.store.commit/release` directly (`receiver/start.ts:114`/`:103`) while the mounted `webhookMiddleware` ALSO auto-finalizes via the `settled`-guarded finalizers (`receiver/hono/index.ts:102-103`). Route bypasses the guard by hitting the raw store. Double-release deletes a tentative entry (`act-ops/idempotency/in-memory.ts:95`), so a concurrent re-claim in the gap gets dropped → third delivery processed twice. Fix: finalize through `c.get("idempotency").commit/release`. *Sibling:* any other receiver/finalizer path that reaches the store outside the `make_finalizers` guard.
- **#1294** — `Store.query_stats` head/tail carries decrypted PII on SQLite (`sqlite-store.ts:1150`/`:1199` select+decrypt `e.pii`) but PG (`postgres-store.ts:1722`) and InMemory (`in-memory-store.ts:1078`) omit it. Undeclared cross-adapter divergence + SQLite disclosure on the introspection surface. The #1277 gate (`load`, orchestrator) never covered `query_stats` (a raw Store method). Fix: pii-safe — strip pii from SQLite's query_stats SELECTs, pin in store-TCK. *Sibling:* any other Store read method (`query_streams`?) that carries the pii sidecar on one adapter only.
- **#1295** — tRPC malformed body → `400 BAD_REQUEST` + raw ZodError (`trpc/index.ts:344` runs `.input(schema)` upstream of `toApiError`) vs Hono `422 / ApiError` (deliberate convergence hook `hono/index.ts:322`). Breaks the guide's "one shape for every framework error" (auto-generated-api.md:12/129). Sibling of #1280/#1286 but pre-dispatch (input-parser seam), not an `app.do` throw. Fix: tRPC `errorFormatter` remaps ZodError→`UNPROCESSABLE_CONTENT`+ApiError.
- **#1296** — partial-success-then-block drops the block for one cycle: `ops.ack` (`drain-cycle.ts:246`) releases the lease before `ops.block` (`:259`), which is gated on `leased_by=by`, so a `{handled>0, block:true}` finalize (succeed on e0, `NonRetryableError` on e1) advances the watermark but no-ops the block. Contradicts the `:231-232` "lands in both" comment and the NonRetryable no-retry guarantee (handler re-runs next cycle). Self-heals next cycle (converges). Fix: run `block` before `ack`. *Sibling:* any other finalize path where ack-release precedes a lease-gated mutation.
- **#1310** — `app.audit(["deprecated-load"])` classifies `_v<n>` deprecation over the **global** event set (`act.ts:784` feeds `_event_to_state.keys()` → `audit.ts:300/310` calls `deprecated_event_names`/`current_version_of` on it), while the builder/registry classify strictly **per state** (`act-builder.ts:368-370`, `registry.deprecated_events(state_name)`). Two symptoms, both need a cross-state base-name collision (legal — event names are per-state-namespaced): (1) false-positive migration finding — `AStar.Approved` (sole version) flagged deprecated toward unrelated `BStar.Approved_v2`; (2) uncaught crash — `CStar.Gadget_v2` + `DStar.Gadget_v02` builds fine but the global set trips the leading-zero collision `throw` (`event-versions.ts:72`) inside a public introspection method. Fix: audit consumes the per-state `deprecated_events` union, not a global recompute. Medium. **✅ FIXED** — `classify_deprecated_by_state` inverts `event_to_state` and classifies within each state's own set; dead `known_events` dep dropped. *Sibling:* any other introspection/audit pass that recomputes a per-state-defined property over `_event_to_state.keys()`.
- **#1311** — `act-notify` `withBroker.commit` **`await`s** the broker hint-publish inline on the durable write path (`with-broker.ts:87`). The `try/catch` bounds rejections, not *duration* — a TCP-connected-but-unresponsive broker (`publish` returns a pending-forever promise; node-redis sets no command timeout) stalls `commit()` forever though `store.commit` already persisted the event. Contradicts the module's own "a broker outage degrades cross-process latency to the poll cycle, **never a commit**" (`with-broker.ts:59-60`). Existing "swallows publish failures" test only covers a *synchronous throw*, never a hung promise. Fix: fire-and-forget the publish (`void Promise.resolve().then(()=>broker.publish(...)).catch(log)`), preserving Loopback's synchronous fan-out. Medium(-high). **✅ FIXED** — publish invoked synchronously, result no longer awaited; sync-throw + async-reject + hung-promise all covered. *Sibling:* any other decorator/hook that awaits a declared best-effort hint on a durability API's return path.
- **#1312** — `act-http/sse` `BroadcastChannel.overlay()` presence/computed-field updates are **silently dropped by live caught-up clients**: `overlay()` emits a patch at the *unchanged* current version (`broadcast.ts:104`, `{ [state._v]: patch }`) but `applyPatchMessage` treats `maxV <= cachedV` as `stale`→no-op (`apply-patch.ts:49`), and a caught-up client has `cached._v === state._v`. Docs (`real-time.md` § Overlays/Presence) recommend `overlay()` for presence consumed via `applyPatchMessage` — the two halves are incompatible. Overlay DID update the LRU cache, so reconnect/fresh baselines include it; only live viewers (the whole point of presence) miss it. Existing `apply-patch.spec.ts` "same version" case pins the drop while its title claims the opposite. Fix (design choice): overlay frames carry a distinct kind/sub-version so live clients apply same-version overlays. Medium. **⏸ DEFERRED** — the fix grows public `act-http/sse` surface (a marker on `PatchMessage`, optionally a new `kind:"overlay"` frame), so it's split to its own RFC + PR rather than bundled with the mechanical fixes. *Sibling:* any other same-version broadcast path assumed to reach live clients through the version-gated applicator.
- **#1313** — `act-otel` `streams_blocked` gauge binds its `collect()` to the **first** app instrumented against a registry: `gauge_on` (`index.ts:52-60`) returns the already-registered gauge on a second `instrument()`, discarding the second bridge's `collect()` closure. In the documented "two Acts, one `/metrics`" deployment, `app2.blocked_streams` is never consulted → app2's parked poison streams read as `0` on the page-worthy gauge (counters share fine — they `.inc()`; a gauge's value comes from one `collect()`). Found by the act-otel lens re-run. Fix: a per-registry Set of `blocked_streams` providers backs one shared `collect()` that sums every live bridge (per-provider try/catch so a degraded store doesn't poison the scrape); disposer removes its provider. Medium. **✅ FIXED** — reproduced red-first (gauge=0 vs 5), green with the fix. *Sibling:* any other gauge whose `collect()` closes over one app while its metric is shared/idempotent across bridges.

### Wave 8 (2026-07-25 — lenses: receiver finalization, versioned events, fold engine, act-ops idempotency)

- **#1335** — `InMemoryIdempotencyStore.maxEntries` eviction drops **committed** keys, allowing duplicate processing. `in-memory.ts:107-112` — LRU eviction evicts the oldest entry regardless of `committed` flag. A committed (durable) key can be evicted, so a new delivery with the same idempotency key is processed as fresh → duplicate side effects. **HIGH** (silently violates idempotency contract). Durable adapters (Postgres unique index, Redis `SET NX`) don't have this bug. *Fix:* evict only tentative entries first; or separate committed budget.
- **#1336** — `commit()` does not run GC → expired entries accumulate until next `claim()` or `size()` call. `in-memory.ts:89-91` calls `_record()` but not `_gc()`. Memory grows unbounded in commit-heavy workloads. **MEDIUM** (memory leak). *Fix:* call `_gc(now)` at start of `commit()` (and `release()`).
- **#1336** — `release()` does not run GC — same leak class. **MEDIUM**. *Fix:* call `_gc(now)` at start of `release()`.

**Ruled out in this wave:**
- **Receiver finalization** — #1293 fix holds; middleware owns finalization; double-finalization guarded by `make_finalizers` closure flag. ⚠️ **CORRECTION (wave 12, #1364):** the "4xx treated as failure (release)" claim here was WRONG — the Hono middleware boundary is `status >= 500 ? release : commit`, so 4xx COMMITS the idempotency key (silent drop of a corrected same-key retry). This note asserted behavior the code never had; it was never verified. Fixed by #1364.
- **Versioned event deprecation** — per-state scoping correct; global event name uniqueness enforced at build time (`register_new_state` throws on duplicate). Cross-state collision impossible in practice.
- **Fold engine** — cold/warm PII paths aligned (#1320); `app.reset()` doesn't need to clear fold cache (shared cache provides snapshot floor).
- **act-ops concurrent claim race** — impossible in single-threaded JS; durable adapters use atomic ops. ABA/TTL expiry by design (`minSafeTtl` sizes window).

### Wave 5 (2026-07-22 — lenses: act-patch, act-pino, scoped ports, projection fold)

- **#1317** — `app.audit()` on a **scoped** Act reads the SINGLETON store, not the tenant's scoped store: `audit()` (`act.ts:1804`) returned the raw async generator, whose body runs lazily during the consumer's `for await` — outside any `_scoped` frame — so `store()` resolves `scoped.getStore()?.store ?? _store()` → the singleton. Even a synchronous `_scoped` wrap around the `return` would unwind before the first `next()` (it's an `async function*`). Symptoms in a multi-tenant deployment: a false all-clear when the singleton is empty, or another tenant's stream stats when it isn't (cross-tenant introspection disclosure). `scope.spec.ts` pinned every OTHER async-boundary path (settle timer, poll, lane worker, reaction chains) but never `audit()`. **HIGH** (security). **✅ FIXED** — `audit()` is now an `async *` that drives the inner generator's `next()` inside `_scoped`, so store() resolves the scoped bag during iteration; non-scoped path (`_scoped(fn)=fn()`) unchanged. *Sibling:* any other public method that returns a lazy generator/iterable delegating to `store()`/`cache()` without entering the scope per step.
- **#1318** — `@rotorsoft/act-patch` `patch()` returns a **prototype-less** object (`Object.create(null)`) for any state with **>16 top-level keys** (`patch.ts:37` — the large-object copy buffer is returned directly), while the `<=16` path returns an ordinary object. Breaks `instanceof Object`, `hasOwnProperty`, `toString`, and prototype-aware equality (`toStrictEqual`, `assert.deepStrictEqual`) on wide production state (folded via `bare_patch`, and the SSE client cache). Reachable with non-adversarial input. Medium. **✅ FIXED** — use `{}` for both branches (keeps the two-pass perf win). *Awareness (unfiled):* the `<=16` path reassigns the RESULT object's own prototype if a delta carries `__proto__` (not global pollution; legit `Patch<S>` callers can't hit it, but the SSE raw-JSON→`deep_merge` wire path could — a `__proto__`/`constructor` guard would close it).
- **#1319** — `@rotorsoft/act-pino` `PinoLogger._log` (`pino-logger.ts:80`) short-circuits on a string payload even when a context `msg` is supplied, **dropping the msg**: `log.error("reason", "label")` emits only `"reason"`. Hits the framework's own `signals.ts` uncaught-exception / unhandled-rejection handlers when code `throw`s / `Promise.reject`s a string (the label identifying WHICH handler fired is lost). Low-medium (observability, not corruption). **✅ FIXED** — gate the short-circuit on `msg === undefined`; when both present, log the label as the message and keep the payload as a field. *(Same-file unfiled nit: `single_line` passed to pino-pretty whose option is `singleLine` → `logSingleLine` silently ignored.)*
- **#1320** — the projection **fold engine** applies different PII transforms on its cold-load vs warm-incremental paths: cold first-sight `load()` (`projection-fold.ts:118`) folds through the actorless `me.view` gate → `[REDACTED]`, while the warm path folds `pii_strip`ped events (`act-builder.ts:627-636`) → key removed. So a folded PII-aware row is `{seen:"[REDACTED]"}` cold vs `{}` warm — non-deterministic by cache warmth, `maxCachedStates` eviction, restart, or rebuild timing (`app.reset` doesn't clear the fold cache). Not a plaintext leak (the wrong value is the sentinel), so below a straight PII disclosure. Medium(-high). **✅ FIXED** — compose the cold-load view with `pii_strip` for sensitive events (fold handler takes the registry's `sensitive_fields` lookup); both paths now strip structurally. *Sibling:* any other first-sight-vs-warm path pair in a stateful cache that applies a transform on only one side.
- **#1309** — `settle()` early-exits over a bounded inert correlate window: the loop's `made_progress` (`settle.ts:113-124`) counts only `subscribed>0 || acked>0 || blocked>0` and **discards `correlate`'s `last_id`**. A window (`limit`, default 100) holding only globally-inert events (types with no reaction) advances the checkpoint but registers "no progress" → loop `break`s before the next window (holding a reactive event) is scanned. Scoped to **dynamic-resolver reactions** (`.to(fn)`); static reactions subscribe up front and are unaffected; `has_dynamic_resolvers===false` apps unaffected (correlate returns `last_id===checkpoint`). Reproduces at the shipped default `limit=100` with >100 inert events before a reactive one. **Distinct from #1254** — the reactive event already exists at a *higher* id when `settle()` runs; this is a loop early-exit, not a watermark-skip (monotonic ids untouched). Medium: self-heals on next commit but an unbounded stall on a quiescent instance with no polling/lane `cycleMs`. **✅ FIXED** — `SettleLoop` counts correlate watermark advancement as progress (unit-tested via mocked deps). *Sibling:* any other catch-up loop whose progress predicate ignores a watermark it itself advances.

### Wave 6 (2026-07-23 — lenses: query_streams+lease, priority lanes, act-ops retry/poison, forget/PII-shred)

- **#1325** — static cross-source reactions to one target split priority from lane. The lane-agreement guard `classify_registry` keys on `(target, source)` (`build-classify.ts:106`), so two static reactions to the same `target` from **different** `source`s with different lanes escape the "lanes don't merge — disagreement is a config error" throw (`:110-116`). `subscribe()` then max-merges priority but last-writer-wins on lane (`in-memory-store.ts:704-706`; SQL adapters UPSERT lane per-subscribe), so `shared` ends up `priority:7` (from the fast reaction) but `lane:"slow"` (last registrant). On an `onlyLanes:["fast"]` worker the high-priority stream is never claimed → silent permanent starvation, no build/runtime signal. `correlate-lane.spec.ts:12-14` even asserts the static path rejects this — false for different sources. Medium. Fix (design choice): (a) widen the guard to per-`target` (throw on any same-target lane disagreement — matches the ACT-1103 intent, recommended), or (b) carry the max-priority reaction's lane through the static dedup like #1255 did for the dynamic path. *Sibling:* any other per-target property (not just lane) that `subscribe` last-writer-wins while the classify guard is `(target, source)`-scoped. **✅ FIXED** — #1327 widened the guard to per-`target` (option a).

### Wave 7 (2026-07-24 — lenses: circuit breaker, defer/temporal, act-http OpenAPI gen, seed/restore)

### The retry budget is spent on the error path only (#1418)

`finalize` returns early when a handler didn't throw, so `blockOnError` only
ever terminates handlers that fail *loudly*. A handler that fails by
overrunning its lease never throws: it completes, submits an ack the store
drops (`WHERE leased_by = by`), and the next claim bumps `retry` again.
Reproduced at store level against Postgres — five rounds of
claim/steal/late-ack left `retry` at 9, `at` at -1, `blocked` false, forever.

Two things follow for future waves:

- **`retry` climbing without the watermark moving is not a store bug.** Every
  adapter bumps `retry` in `claim` and resets it in a successful `ack`; the
  climb is the budget accruing correctly. The gap was in who consults it.
- **The consultation now also happens at claim time**, gated on
  `blockOnError` and on `retry` **strictly greater** than `maxRetries`. Do not
  "fix" that to `>=`: a stream legitimately reaches `retry === maxRetries` on
  its final attempt and is entitled to run it. Only `>` is unreachable
  without lease loss.

Also settled: the losing worker can never repair this itself. Both `ack` and
`block` are gated on `leased_by = by`, so an evicted holder's writes are
no-ops by construction. Any fix has to run on the *next* holder, which is why
it lives at claim and not at ack.

**And a lesson about proving it.** The first version of this fix shipped with
tests that mocked `store.ack` to return `[]` and rewrote `retry` on the way
out of `claim` — they proved the guard fires when hand-fed the state, not that
the state ever occurs. The real reproduction lived in a throwaway probe that
got deleted. Lease theft is directly reproducible in a committed test: two
`Act` instances over one store, a handler parked on a promise the test
resolves, and a 1ms lease left to lapse. Deterministic (the park removes the
race; only expiry touches the clock) and it runs on InMemory and Postgres
alike. When a finding is about concurrency, the test has to contain the
concurrency — a mock of the losing side's return value is a restatement of
the hypothesis, not evidence for it.

## Wave 19 follow-up: the dynamic-resolver guard family (#1563, #1564, #1567)

Three findings, one root cause: **a build-time guard structurally cannot see a
`.to(fn)` resolution.** The target, lane, and priority are a function until an
event arrives, so every `classify`/`build_events` check exempts dynamic
resolvers with a `continue`. That exemption is correct — the information does
not exist yet — which means the fix never belongs in the guard. It belongs
where the answer first exists: correlate (lane, target) or drain (payload).

Two rules for a future hunter working this seam:

- **Log and continue, never throw.** A throw inside correlate pins the
  checkpoint for the whole app (#1420); inside drain it reaches the circuit
  breaker as a store failure and stalls every stream. "The static form throws,
  so the dynamic form should throw" is the wrong inference.
- **Check the type layer before rating severity.** `TLanes` already rejects an
  undeclared lane at *compile* time for the static and dynamic forms alike, so
  #1564's runtime hole is reachable only by bypassing types — JavaScript
  callers, a cast, or a helper whose return type widens `lane` to `string`. The
  hunter's repro used a cast and did not say so, which read as higher severity
  than the defect carries. A finding that requires a cast to reproduce must
  state that plainly.

**Correct by design, do not re-flag:** a lane disagreement between two dynamic
resolutions is *reported* but not corrected. The lane a live stream carries is
the one its in-flight leases were taken under, so re-laning mid-run would move
a stream out from under a worker holding it. Re-laning is restart-driven; that
is the documented contract, not an oversight.
