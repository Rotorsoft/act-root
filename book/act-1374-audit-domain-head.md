# The head that wasn't the head

A stream's head event is the last thing that happened to it, and half the audit's categories are built on that idea. Is the head a terminal event the operator named? Then the stream is a close candidate. Does the head belong to a state that declares a snapshot reducer? Then a restart is supported. Is the head a framework marker, something starting with a double underscore? Then the stream is already closed or mid-truncate, and there is nothing to advise about.

That last check is the one that ate the feature.

Snapshots are events. When a state's snapshot predicate fires, the framework commits a `__snapshot__` right behind the domain event that triggered it, at a higher id, on the same stream. So for any state that snapshots at all, the head is very often not the domain event. It is the snapshot. And the audit's shared statistics scan asked for heads without excluding anything, which meant the head-is-a-marker check fired on healthy, active, snapshotting streams and quietly dropped them.

Work through what each category then reports. Close-candidate: an order that shipped, whose last domain event is exactly the terminal event the operator listed, is never offered for closing. Not once, and not later — more traffic only produces more snapshots, so the head stays a marker forever. Restart-candidate is bleaker in a way that is almost funny: it reports large streams whose state declares a snapshot reducer, which is to say it targets snapshotting streams specifically, and snapshotting streams are precisely the ones whose head is `__snapshot__`. The category dropped its own entire target population.

There is a third symptom that looks unrelated until you find the root. The deprecated-load category decides whether a legacy event is worth migrating by computing its share of all events, and the denominator was the raw histogram, snapshots included. So the same domain data crosses or misses the reporting threshold depending on whether the state happens to snapshot. A migration signal that moves when you change your snapshot policy is not a signal.

The framework already knew the answer here, in the file next door. The close cycle resolves stream heads through a helper that excludes the snapshot marker, because it needs a domain head to reason about, and a ticket had already been spent learning that a synthesized autoclose reaction reading raw heads sees snapshots and never matches its terminal event. That was the same bug in a different consumer. The knowledge was written down, in code, one module away, and the audit did not inherit it.

So the fix is to exclude the snapshot marker from the shared scan. What makes it more than a one-liner is the asymmetry underneath it. Tombstones are excluded from nothing, deliberately: a tombstoned stream genuinely is closed, and the marker check is exactly the mechanism that recognizes it. One marker is noise obscuring the head; the other marker *is* the head. Treating both as "framework junk to filter" would trade this bug for its mirror image.

The second complication is that excluding snapshots from the histogram removes the number two categories were reading out of it — how many snapshots a stream has. Snapshot-drift and restart-candidate both want it. The answer is to stop asking the shared scan for it. Both categories already narrow to a small candidate set before they need the figure, and one of them already ran targeted per-stream queries in its finalize hook for exactly this reason. Now both do. That preserves the module's actual efficiency contract, which is not "one query" but "a bounded number of full-table walks, with follow-up work proportional to candidates."

The thing worth carrying forward is about tests, not heads. Every existing close and restart test wrote its events through the raw store, because that is the direct way to arrange a fixture. The raw store never produces a snapshot. So the entire class of bug lived in the gap between how the tests created data and how the framework creates data, and no amount of adding cases in that style would have found it. There was even a test named for skipping framework-marker heads, tombstoned and snapshot both, that only ever committed a tombstone — the snapshot half of its own title was asserted nowhere. A test that names a behavior it does not exercise is worse than no test, because it answers the question "is this covered?" wrongly, and it answers it in your own handwriting.
