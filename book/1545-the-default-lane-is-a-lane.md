# The default lane is a lane

Lanes exist so that a slow reaction and a fast one stop sharing a queue. Declaring one spawns a second drain controller, and every controller filters its claim by the lane it owns. Apps that never declare a lane get a small courtesy on top of that: their single controller is built with no lane at all, so the adapter's claim keeps the shape it had before lanes existed and the query planner sees the same statement it always saw. The courtesy is worth having. The condition that decided when to grant it asked about the wrong set.

It asked about the active lanes, the ones this process is actually running, rather than the declared ones, the ones the app knows about. Most of the time those are the same list. They stop being the same the moment a worker boots with `onlyLanes`, which is the whole point of `onlyLanes`, and they collapse into something indistinguishable when a worker boots with `onlyLanes: ["default"]`. From inside the predicate, an app that declares a slow lane and a worker told to run only the default lane looks exactly like an app that has never heard of lanes. Both present a single active lane named default, so both got the courtesy, and the controller was built without a lane.

That would be harmless if a missing lane meant the default lane. It does not. The lane argument on `claim` is an optional filter, and omitting a filter selects everything, so the worker that had been narrowed to one lane widened itself to all of them. The documented process-per-lane deployment then ran backwards. The default worker claimed the slow lane's streams and ran its handlers, and the worker that owned that lane, that had been given its own hardware and its own lease budget for exactly this reason, woke up to find nothing to do.

The stolen work also ran on the wrong clock. Lane defaults are looked up by lane name, and the default lane can never carry a `LaneConfig` because declaring one is rejected as a reserved name, so the thief was holding the fallback lease while running a handler someone had sized for thirty seconds. A handler that outlives its lease has its ack dropped by the guard that checks who holds the stream, which leaves the watermark parked while the retry count climbs, and a stream that is making no progress eventually blocks for reasons that have nothing to do with the handler. The startup advisory, meanwhile, printed the opposite of what was about to happen. It announced that the slow lane was orphaned on this instance and that no controller here would claim its streams, roughly twenty milliseconds before this instance claimed them.

Two other repairs were available and both were worse. One was to let the default lane carry a config so at least the budget matched, which treats the injury rather than the cause and grows surface on a name that is reserved precisely so nobody configures it. The other was to teach every adapter that an absent lane means the default lane, which changes a port contract, forces three stores and any third party's to move together, and destroys the courtesy it was trying to preserve, since a lane-free app would suddenly be filtering on a column it never populates. The predicate simply needed to ask its own question. The collapse belongs to apps that never declared a lane, and that is a property of the declaration, not of what this process happens to be running today. Once any lane exists, the default lane is an ordinary lane and gets filtered like the rest.

The regression is pinned by two workers built from the same builder over the same events, one narrowed to the default lane and one to the slow lane, each asserting that the other's handler never ran and that the drain acked exactly one stream. Written before the fix, the first of them reported that the default worker had run both handlers, which is the failure in one line. A third case pins the budget half, showing the default controller carrying no configured lease and the slow controller carrying its declared one, which is why the filter has to hold: the only controller that may claim a lane's streams is the one holding that lane's clock.
