# The registry that only ever grew

Every Act ever built stayed alive for the life of the process. The constructor ended with one friendly line, `dispose(() => this.shutdown())`, which handed the global cleanup registry a closure so that a Ctrl-C would tear the instance down properly. The registry was a module-level array, and the only thing any code ever did to that array was push onto it. Nothing removed an entry, and the closure captured the Act, so the Act stayed reachable. `shutdown()` did its job faithfully, stopping the correlation worker, the settle cycle, the breaker, the drain controllers, and the notify subscription, and none of that mattered to the garbage collector, because the registry still held the closure and the closure still held the instance.

For a single long-lived application this is invisible, which is why it lived so long. The framework encourages exactly the shape where it stops being invisible. Scoped Acts are documented as an ergonomic pattern, one builder and N tenants, and a scoped Act carries its own store and cache, so each leaked instance drags a connection pool and a cache along with it. Per-request and per-job Acts have the same shape. So do the test helpers: `fixture` and `sandbox` build one per test, and a long suite accumulates them for the whole run. The secondary effect is quieter and follows from the same fact, that process teardown walks every disposer ever registered, so shutdown cost grows with the leak.

The obvious repair is to let a registration be undone. Return a handle from `dispose(fn)` and let the caller deregister, the way every event emitter in the world works. It does not fit here without a fight, because `dispose()`'s return value is already the trigger function, which is public surface that tests and bootstrap code call as `dispose()()`. Adding a deregistration path means either hanging an `off` property onto a returned function, which is the kind of API that reads like a riddle, or introducing a second exported function, which is new charter-covered surface for what is fundamentally a bug fix. There was a smaller version of the same idea, an internal removal path used only by `Act`, but it leaves third-party disposers un-removable and, worse, only helps the instances that get shut down explicitly. The multi-tenant case is precisely the one where a tenant object is dropped without ceremony.

What the situation actually calls for is a change in who holds whom. The registry does not need a strong reference to the thing it cleans up. If the entry holds a weak reference, then an Act that becomes unreachable is collected regardless of whether anyone remembered to shut it down, and its entry is skipped at teardown because there is nothing left to clean up. That is not a workaround for the missing deregistration API; it is the correct ownership. A cleanup registry that keeps its subjects alive has inverted its own purpose.

The change is small and lives entirely inside the framework. The registry moved into an internal module that stores entries as a run function plus an optional weak reference, `Act` registers through the weak path, and the public `dispose` and `disposeAndExit` keep their exact shapes. Dead entries are dropped whenever anything else registers, which keeps the array proportional to live objects rather than to every object ever built, closing the secondary half of the bug without a separate mechanism. One detail was worth resisting: an early draft had teardown empty the array as it ran, which is tidier and would have silently changed what a second `dispose()()` does. Existing behavior was left alone.

Two things about proving it are worth passing on. The first is that a guarantee about releasing memory cannot be tested by hoping for a collection, so the weak reference is accepted as a structural shape rather than a concrete `WeakRef`, which lets a test hand in a stub that reports its target as collected on command. The mechanism is then pinned deterministically, and the real collection check becomes corroboration rather than the whole proof. The second is that the corroboration nearly lied. The first version of the garbage-collection test built each Act in the test body, and V8 keeps a binding in the current frame reachable until that frame returns, so the last instance always looked retained no matter how correct the fix was. Moving the allocation into a helper function fixed the measurement. The test that was reporting a failure was measuring itself.

It was also worth making that test run. It had been written to skip unless the process was started with the flag that exposes the collector, which in practice means skipping always, and a contract nobody executes is the exact failure mode the behavior-contract checklist exists to prevent. Passing the flag to the test workers costs nothing and turns the row in that checklist into something with teeth. Before the fix it reports five of five instances retained; after it, zero.

The principle generalizes past this bug. A registry, a cache, an observer list, or any structure that exists to serve objects rather than to own them should hold them weakly, because the alternative is that the helper outlives everything it was meant to help. The same reasoning shows up wherever the framework keeps per-target state, and it is the reason a lease is bounded in time rather than held until someone remembers to release it.
