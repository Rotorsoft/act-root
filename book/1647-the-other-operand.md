# The other operand

Some bugs come in pairs, and the second one is always more embarrassing than the first, because by then somebody has already stood in front of the machinery and understood it.

Teardown in Act has to decide how long to wait. When a process is asked to shut down, cycles may still be running, and abandoning them means the work is discarded and redelivered later, and any listener watching for their outcome never sees it. So `shutdown()` takes a grace budget, and when the caller does not supply one it derives it. The derivation is a fold over whatever is in flight: for each lane with a cycle running, take its configured lease, which is the operator's own statement of how long one of their handlers may hold a stream, and use the largest. A lane running a cycle without having pinned a lease has nothing to offer, so it contributes the runner's own ten-second fallback instead.

The first bug in that fold was the seed. When the only thing in flight was a settle rather than a lane cycle, the loop had nothing to iterate, the fold started at zero and stayed there, and teardown looked at a budget of zero and returned immediately, without waiting for the settle it was about to wait for. That was fixed by seeding the fold with the fallback whenever a settle is in flight, and the fix came with a test and a line in the contract table.

The second bug is one operator further along the same line. Inside the loop, a lane's lease is read as "its value, or the fallback if it has none," and the coalescing is written with the operator that treats only null and undefined as absence. Zero is not absent. A lane configured with a zero-length lease therefore contributed a literal zero, the fold's maximum came out zero, and teardown returned instantly having just enumerated the cycle it was abandoning. The seed had been fixed and the members had not.

The natural objection is that nobody configures a zero-length lease, and the natural answer is that the codebase had already decided otherwise. The schema for lane configuration admits zero explicitly, and an earlier ticket had gone to the trouble of making a zero-length lease behave correctly at the store, on the reasoning that it is legal configuration reachable from type-checked source. Once one part of the system has committed to a value being real, every other part that quietly treats it as absence is wrong, and the disagreement will surface somewhere inconvenient.

What makes this worth writing down is not the character that changed. It is that the correct behavior was already sitting in the function's own doc comment, one paragraph above the defect. The comment said that a lane which pinned no lease contributes the fallback. A zero-length lease is expired at the instant it is granted, which means it pins nothing; it is the no-lease case spelled with a number instead of an omission. The prose and the code had different ideas about what counts as absence, and the prose was right. Reading it would have been enough, which is a thing worth noticing about defensive code generally: the comment explaining why a fallback exists usually also tells you which values ought to reach it.

Two tests pin it now, and they pin it from different directions on purpose. One measures the budget by advancing a fake clock and asserting the wait ends at ten seconds rather than immediately. The other never touches the clock: it parks a handler on a zero-lease lane, calls shutdown with no argument, and asserts the call has not returned while the handler is still parked. The second exists because the first could keep passing if the derivation stayed right while something else in teardown stopped honoring it, and because the default path is the one `dispose()` uses, which makes it the path that actually runs in production.

Both were confirmed red against the unfixed code before being kept. That step is not ceremony here. The whole family of bugs in this fold is about a value that quietly becomes zero, and a test written after the fix, asserting a budget that is now correct, would pass just as happily against a version that returned instantly if the assertion had been aimed slightly wrong. Watching it fail first is what tells you the test is pointed at the defect rather than near it.

The seed half of this fold is its own essay, and reading the two together is the point: a fix that lands on one operand of an expression and not the other is a recognizable shape, not bad luck.
